# Architecture

How the code is arranged and why. Read this before adding a page or changing a shared component.

## The shape of it

One Astro app, statically built, no client framework. Fifteen routes in each language, 30 pages in total, and
the markup for each is written once:

```
src/views/Home.astro          ← the whole page, takes { lang }
src/pages/index.astro         ← <Home lang="en" />
src/pages/zh/index.astro      ← <Home lang="zh" />
```

That split is the central decision. A view is a normal Astro component with a `lang` prop; the route files are
three lines each, 22 of them across the two trees. Nothing inside a view knows which language it is in except through `getContent(lang)`, so
adding a third language is a dictionary plus a route tree, not a rewrite.

## By the numbers

| | |
| --- | --- |
| Routes | 15 per language, 30 pages, 175 files in `dist` |

| Images | 62 sources, 127 derivatives at 480/900/1600 px |

## Directories

| Path | Responsibility |
| --- | --- |
| `src/views/` | 11 components, one per page. All markup lives here. |
| `src/pages/` | Route wrappers only. `pages/zh/**` mirrors `pages/**`. |
| `src/i18n/` | Language layer: dictionaries, Chinese collections, the `getContent` merge. |
| `src/data/` | The English content model (626 lines) and the generated image manifest. |
| `src/components/` | 6 shared components: Header, Footer, Img, Search, Lotus, Divider. |
| `src/layouts/Base.astro` | `<html>`, head, metadata, hreflang, global scripts. |
| `src/styles/global.css` | The entire design system in 1,611 lines. |
| `src/lib/` | `url.ts` (link building) and `routes.ts` (sitemap). |
| `public/media/`, `public/fonts/` | Generated derivatives and self-hosted fonts. |
| `tools/` | The offline pipeline. Nothing in `site/` imports from here. |

## The language layer

`getContent(lang)` returns one object containing everything a view needs:

```ts
const { t, isZh, stats, programs, schedule, events, quotes, branches } = getContent(lang);
```

- `t` is the interface dictionary (`en.ts` / `zh.ts`), typed as `Dict` so a missing key in either file is a
  compile error.
- The rest are collections, picked from `src/data/` or `src/i18n/zh-data.ts` by language.

`en.ts` and `zh.ts` must stay structurally identical. When you add a key to one, add it to the other, or
TypeScript will not accept the object.

### Links

Never write a path by hand. Two helpers in `src/lib/url.ts`:

```ts
href("/programs/", lang)        // /bodhinature/programs/ or /bodhinature/zh/programs/
oppositeHref(pathname, lang)    // the same page in the other language, for the toggle
```

`href` reads `import.meta.env.BASE_URL`, so the base path is applied once and works in every environment.
`oppositeHref` strips or adds the `/zh` prefix and keeps the hash, which is why the language toggle lands on
`/contact/#connections` rather than the top of the page.

### Adding a route

1. Write `src/views/Thing.astro` taking `{ lang }` and calling `getContent`.
2. Add `src/pages/thing.astro` and `src/pages/zh/thing.astro`, each three lines.
3. Add the path to `src/lib/routes.ts` (`zhRoutes` derives the Chinese tree automatically, so the sitemap and
   the search index both pick it up).

## The content model

`src/data/site.ts` holds the prose in 626 lines as typed collections: `site`, `stats`, `pillars`, `path`,
`teachers`, `programs`, `schedule`, `retreat`, `volunteerRoles`, `donateMethods`, `branches`, `connections`,
`testimonials`, `books`. `quotes.json` holds the 14 sayings. `events.ts` holds 2 events and the "also running"
posters. The Chinese mirror, `src/i18n/zh-data.ts`, is 568 lines and matches it key for key.

It is a content model, not a CMS. There is no runtime fetch and no build-time generation from the archive: the
copy was transcribed and edited by hand from the harvested blocks, and that is what ships.

Two rules that keep it honest:

- **No invented data.** If the source did not publish a date, address or time, the field is absent and the
  view omits the row. `Event` has optional `time`, `place` and `image` for exactly this reason.
- **Collections are typed**, so a view can rely on a `program` having `slug`, `title`, `summary` and
  `highlights`, and on an event maybe not having a poster.

## Images

`src/data/images.json` is generated by `tools/process_images.py`. It maps 62 semantic names to the variants
that exist and the intrinsic size, producing 127 derivatives:

```json
"hero": { "src": "hero", "width": 2000, "height": 715, "variants": [480, 900, 1600] }
```

`<Img name="hero" alt="…" sizes="…" />` builds the `srcset`, picks a sensible `src`, and — importantly — sets
`width`/`height` from the manifest so nothing shifts while loading. Any image missing from the manifest throws
at build time rather than rendering a broken tag.

Names are semantic, not filenames: `hero`, `program-dharma`, `branch-canada`, `teacher-zhenjue`. Renaming a
source file in the WordPress install does not break the site.

## Styling

One file, `src/styles/global.css`, 1,611 lines. It holds design tokens as custom properties (`--paper`,
`--ink`, `--saffron`, `--maroon`, `--gold`, `--jade`, a type scale built on `clamp()`), then components,
then two media-query layers at 1,120, 980, 900, 720 and 390 px.

Three conventions matter:

- **Component styles live next to their markup only when they cannot be shared.** Anything that must style a
  child component's `<img>` (`.media`, `.zoom`, `.pay-mark`) lives in `global.css`, because Astro scopes
  styles to the component that declares them and a parent cannot reach into a child's elements.
- **Dark bands are a modifier**, `.section--ink`, `.section--jade`, `.section--retreat`, not bespoke colours
  per page.
- **Chinese has its own rules**, keyed off `html[lang="zh-Hans"]`: Songti/Source Han headings, PingFang body,
  line-height 1.8, `line-break: strict`, and italic disabled in favour of a saffron accent, since CJK has no
  true italic and synthetic slant looks wrong.

## Scripts

Everything client-side is inline in `Base.astro` or in the component that needs it, and is progressive: the
site works fully without JavaScript except for the search palette and the quote rotator.

- **Header**: adds `is-solid` after scroll; toggles the mobile drawer.
- **Reveal**: an `IntersectionObserver` adds `is-in` to `[data-reveal]`. Content is present in HTML; the
  animation only transforms it. Under `prefers-reduced-motion` the observer never runs.
- **Search**: fetches the per-language JSON index on first open (⌘K), 7.5 KB English or 8.8 KB Chinese, and
  filters client-side.
- **Rotator**: advances the quote every 7 seconds, pauses on hover and on `visibilitychange`.

Total 2.7 KB inline on a median page, 3.2 KB at most, no bundles.

## Two things that are easy to get wrong

**Astro's preview server reads `allowedHosts` from `server`, not `preview`.** Set it in the wrong place and
every request by hostname gets a 403 while the IP works fine.

**Scoped CSS cannot reach child-component markup.** If a rule depends on an element defined in another
component, it belongs in `global.css` with `:global()` only as a last resort.
